# Findings — Meilenstein 2

Format: `- [ ] → Phase N: <Erkenntnis>` — offen, bis die betroffene Phase sie eingearbeitet hat.

- [x] → Phase 2, 4: Neue Listen-Tabellen gehören an zwei Stellen eingetragen: `RecordMerger::TABLES` (Schlüssel, abgleichbare Spalten) und `RecordRepository::ORDER` (Sortierung). Das Repository hat keinen `$orderBy`-Parameter (Abweichung von der Phasen-Datei, Sortierung bleibt Konstante). Phase 2: Ereignisse laufen über das eigene `EventRepository` (Lesen mit Werkstatt-Join), nur `TABLES` ist ergänzt. Phase 4 prüft für Messwerte/Reifen/Teile/Schäden selbst, ob `RecordRepository::ORDER` reicht.
- [x] → Phase 5: Die Prüfung von `open_items.proposal_json` und `audit_log.vehicle_id` ist in Phase 1 und 2 nur im Code belegt (kein Lese-Zugang von außen). Sobald der Verlauf/die Klärfall-Liste Daten liefert, per `curl` gegenprüfen — auch die Vorschläge der Phase 2 (`proposal.items` bei Positionen, `proposal.conflicts_with` bei Kilometerständen). Die JSON-Spalte sortiert Objektschlüssel um: Vergleiche über `EventService::sortedKeys`, nie über die Schlüsselreihenfolge.
- [x] → Phase 3: Die Fälligkeit liest Kilometerstände nur über `OdometerService::validReadings` (Status `gueltig`, strittige und verworfene Stände zählen nicht). Ausführungen kommen aus `events` + `event_items.task_key` (Spalte seit Migration 009 vorhanden, noch ohne Bezug zu `tasks`).
- [ ] → Phase 7: Die Testkonten aus Phase 2 (`p2ra-…`, `p2rb-…`, `p2rc-1794910740@example.com`, Garagen „Test A P2“, „Test B P2“) passen nicht auf das Muster `test-%@example.com`; die Sperr-Migration muss sie ausdrücklich nennen. Dazu zwei nie angenommene Einladungen („Probe“, „Probe2“, laufen nach 7 Tagen ab). Phase 3 legt weitere Testkonten an (`test-m2-p3a-…`, `test-m2-p3b-…`, `test-m2-p3ro-…@example.com`, Garagen „Test A P3 …“, „Test B P3 …“); sie passen auf das Muster `test-%@example.com`. Ein erster Prüflauf brach nach dem Anlegen eines Kontos ab: ein weiteres Konto `test-m2-p3a-…` (anderes Suffix) ohne Token.
- [x] → Phase 4: Messwerte, Reifen, Teile und Schäden dürfen Kilometerstände nur über `OdometerService` anlegen (Vorwärts-Regel); ein `task_key` an einer Position braucht eine Regel (`upsert_task_rule`), sonst warnt `record_service_event`. Teile mit Wechselintervall (Reifen, Batterie) können über `task_key` in den Wartungsplan laufen.
- [x] → Phase 6: Lese-Bausteine für die Akte aus Phase 4: `MeasurementService::series`, `TireService::list` (mit `dot_age_years`, `mounted_set_id`), `PartService::grouped`, `DamageService::listDamages`/`listRecalls`, `NoteService::listCurrent` (neueste Revision je Thema; ältere Revisionen hat noch kein Lese-Weg). Jede prüft `VehicleAccess::readable` selbst. `get_vehicle` bleibt ohne diese Listen.
- [ ] → Phase 7: Testkonten aus Phase 4: `test-m2-p4a|p4b|p4ro-<Zeitstempel>@example.com`, zwei Läufe (`1794912532019` und ein späterer; Garagen „Test A P4 …“, „Test B P4 …“), passen auf `test-%@example.com`; `p4ro` ist Mitglied mit Rolle `lesend` in „Test A P4“. Die Messwert-Beispiele legen zusätzlich Klärfälle und Notizen an den Testfahrzeugen an.
- [x] → Phase 3: 🟡 Direkt nach einem Deploy lieferte Strato einmal kurz noch das alte Verhalten (vermutlich OPcache). Nach einem Deploy vor der curl-Prüfung etwa eine Minute warten; bei „Fix wirkt nicht“ erst nochmals prüfen, dann den Code verdächtigen.
